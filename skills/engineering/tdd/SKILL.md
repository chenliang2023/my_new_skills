# Test-Driven Development

TDD 是 红 → 绿 循环。本 skill 是让这个循环产出值得保留的测试的参考：什么是好测试、测试放哪、反模式、循环规则。每个 section 在每个 cycle 都适用：在循环开始前和进行中查阅，不是循环结束后。

服务器端 agent（DeepSeek Harness / Pi / AntiGravity）在实现 ticket 时都应遵守此规范。

## 什么是好测试

测试通过公共接口验证行为，不验证实现细节。代码可以完全重写，测试不应该变。好测试读起来像规格说明："用户可以用有效购物车结账"准确告诉你存在什么能力，且它在重构后仍然有效，因为它不关心内部结构。

## Seam：测试在哪

**seam** 是你测试的公共边界：你观察到行为的接口，不深入内部。测试在 seam 上，绝不在内部上。

**只在预先确认的 seam 上测试。** 写任何测试前，写下测试的 seam 并与用户确认。不在未确认的 seam 上写测试。

ticket 的 `## 测试 seam` 字段就是预先确认的 seam。照它执行。

## 反模式

- **实现耦合**：mock 内部协作者，测试私有方法，通过旁路验证（查数据库而不是用接口）。特征：重构但行为没变时测试就坏。
- 同义反复：断言用代码同样的方式重算期望值（`expect(add(a, b)).toBe(a + b)`），所以按构造通过，永远不会和代码不一致。期望值必须来自独立真值源：已知正确的字面量、worked example、spec。
- **横向切片**：先写所有测试，再写所有实现。批量测试验证的是想象的行为。用**纵向切片**替代：一个测试 → 一个实现 → 重复，每个测试是对上一 cycle 教训的响应。

## 循环规则

- **红先于绿。** 先写失败测试，然后只写够让它过的代码。不预写未来测试或加投机功能。
- **一次一个切片。** 一个 cycle 一个 seam、一个测试、一份最小实现。
- **重构不属于循环。** 它属于 review 阶段（见 `/code-review` skill），不是红 → 绿实现 cycle 的一部分。

## 在本工作流中的位置

- 本 skill 是 model-invoked：agent 实现 ticket 时自动遵守，不需要用户手动调用
- ticket 的 `## 测试 seam` 字段已经定义了 seam
- 实现完成后，`/verify` 会运行全量测试套件做最终检查
